# V2-04 — Source-Backed Evidence RAG & Research Engine Architecture

## Overview

The V2-04 module establishes the **Source Research Engine** and **Evidence RAG Foundation** for the Carpet Style & Story Match project.
It bridges verified visual motif subjects to authoritative, institutionally backed cultural evidence while guaranteeing **ABSOLUTE SAFETY AND PROVENANCE INVARIANTS**.

---

## 1. Frozen Hybrid Architecture

NO single LLM or VLM model owns the full pipeline. The system enforces strict separation of concerns across deterministic computer vision, reference visual verification, curator review gates, evidence retrieval, cultural claim validation, and story rendering:

```
IMAGE
  ↓
QUALITY / RECTIFICATION
  ↓
┌─────────────────────────────────────┐
│ VISUAL EVIDENCE (Deterministic CV)  │
│ - Style DNA                         │
│ - Color & composition observations  │
│ - Region proposals                  │
│ - Reference VLM visual verification │
└──────────────────┬──────────────────┘
                   ↓
             MotifCandidate
                   ↓
              REVIEW GATE (Curator Confirmed / Verified Canonical)
                   ↓
             VERIFIED MOTIF
                   ↓
              Evidence RAG (V2-04)
                   ↓
              EvidencePack (evidence-pack-v1.0.0)
                   ↓
             Claim Validator (V2-05)
                   ↓
            Story Presentation (V2-05)
```

## 2. Model Roles & System Boundaries

- **`Qwen/Qwen2.5-VL-3B-Instruct-AWQ`**: Function: **`REFERENCE_VISUAL_VERIFIER`**. It MUST NOT become a cultural reasoner, cultural knowledge base, or story generator.
- **YOLO11n / OBB (Future)**: Function: **`MotifRegionProposalProvider`**.
- **Evidence RAG Engine (V2-04)**: Function: **`SourceResearchProvider`**. Performs neutral academic query expansion, source tier filtering, chunking, locator traceability, and EvidencePack assembly.
- **Claim Validator & Story Curator (V2-05)**: Function: **`CulturalClaimValidator`** & **`StoryPresentationCurator`**.

## 3. Cultural & Material Safety Invariants

### 1. Visible Color Safety Rules
- **`VISIBLE COLOR != DYE MATERIAL`**: Visual RGB or Lab color observations (e.g. deep warm red, indigo-like blue, yellow-green) DO NOT establish dye material. Forbidden: `RGB -> madder confirmed`, `RGB -> indigo confirmed`. Material defaults to `UNKNOWN` unless backed by direct material source evidence.
- **`COLOR != CULTURAL MEANING`**: Static symbolic color rules (e.g. `red -> love`, `blue -> protection`, `green -> sacred`) are FORBIDDEN as deterministic outputs. Color meaning is contextual research, requiring source-backed validation.

### 2. Research Input Gate
- Research MUST NOT start from arbitrary `AI_CANDIDATE`, `UNMAPPED_MOTIF_CANDIDATE`, or `ABSTAINED` proposals.
- Research calls for unverified candidates are strictly **BLOCKED** (`BLOCKED_NOT_VERIFIED`).

### 3. Neutral Query Expansion
- Queries generated by `ResearchQueryBuilder` (`cultural-research-query-v1.0.0`) MUST remain neutral.
- Visual taxonomy categories (e.g., `repeating_geometric`, `prayer_niche_like`) MUST NOT determine research culture.
- Forbidden query generation: `repeating_geometric -> "Seljuk carpet"`, `prayer_niche_like -> "Islamic prayer rug"`.

## 4. Source Quality Tiers & Policy (`source-quality-policy-v1.0.0`)

| Source Tier | Description | Examples |
| :--- | :--- | :--- |
| **`TIER_1_PRIMARY_INSTITUTIONAL`** | Museums, government cultural institutions, university archives | MET Museum, V&A Museum, Louvre, Turkish Ministry of Culture |
| **`TIER_2_SCHOLARLY`** | Peer-reviewed journals, academic monographs, scholarly catalogues | Academic journals, university press publications |
| **`TIER_3_REPUTABLE_SECONDARY`** | Established cultural heritage references, encyclopedias | Cultural archives, heritage reference works |
| **`REJECTED_SOURCE`** | Unverified blogs, social media, commercial product/dealer sites | Pinterest, Etsy, eBay, commercial carpet seller sites (Merinos, Dinarsu) |

*Note*: Commercial carpet manufacturer product pages (e.g. Merinos, Dinarsu) are valid **Product Catalog** sources, but are strictly **REJECTED** as cultural symbolism evidence.

## 5. EvidencePack Schema Contract (`evidence-pack-v1.0.0`)

The `EvidencePack` schema (`data/schemas/evidence-pack-v1.schema.json`) enforces strict traceability and forbids claims or narrative prose:

- **Mandatory Locators**: Every `EvidenceUnit` MUST specify a non-empty locator (page number, catalog entry, object ID, section heading).
- **Copyright Excerpts**: Excerpts are short and copyright-bounded (max <= 300 characters).
- **Forbidden Fields**: Top-level keys `final_claim`, `symbolic_meaning`, `story`, `cultural_truth`, and `narrative_prose` are **STRICTLY FORBIDDEN**. Attempts to include them raise validation errors.
- **Contradiction Detection**: Discrepancies across evidence sources produce `EvidenceConflict` records without auto-resolving winners in V2-04.

## 6. API Endpoints

- `POST /api/v1/research/evidence-pack`: Executes source research for a verified motif subject and returns a validated `EvidencePack`.
- `GET /api/v1/research/provider-status`: Exposes research engine provider status, quality policy version, and active provider modes.
